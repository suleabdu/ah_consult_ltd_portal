# Native Identity Profiles, Active Styles and Legacy PDFs

Document Designer supports multiple institution-owned branding identities. Each identity has a short label, institutional fields, optional compact logo, style alignment and a revision number. Saving an active identity creates a **new draft** rather than mutating the currently published identity; other draft profiles may be edited. `Publish / Set default` is the deliberate promotion step. Exactly one profile may be the default at a time, enforced by a partial unique database index and a serialized SQL publisher function.

The institution-wide published identity is replicated to `institution_document_identity` in the **same database transaction** to maintain backward compatibility with the PDF renderer. New documents and safe sample previews use this identity automatically across portals. Published logos may be detached; physical storage objects are deleted only when no identity references them. Default profiles cannot be deleted until another is made default.

**Document integrity:** An archived officially issued PDF is a historical artifact and is served byte-for-byte with SHA-256 validation. Branding changes do not rewrite it. When a logged-in student prints an eligible issued document with updated styling, the backend may generate a new distinct **updated-style reprint** from current verified source records and the originally frozen template wording. It is stored with a separate SHA-256 fingerprint, the source PDF hash, and identity revision. A style reprint does not change the underlying original document or confer new authorization. Academic copies still require review and registrar approval; certificates cannot be automatically reissued. For documents without an immutable template snapshot, use the original or an explicitly authorized reissuance procedure.

Roles: only approved administrators can edit, delete or publish identities. A valid Supabase user access token is checked inside `document-branding`; disabling gateway JWT verification is solely for compatible authenticated requests and consistent CORS responses.
